# Передача лендинга «СравниПлитку»

Статическая страница без сборки: HTML, CSS и ES-модули, форма заявки на PHP.
Открывается на любом хостинге. Ни `node_modules`, ни сборщика, ни npm-скриптов
здесь нет и не требуется.

Состояние на 26 августа 2026. Живое превью: https://xenaja.github.io/sravniplitku-landing/

---

## Что внутри

| Путь | Что это |
|---|---|
| `index.html` | сама страница, один файл |
| `docs/privacy.html`, `docs/terms.html`, `docs/requisites.html` | политика обработки ПД, права на изображения, реквизиты. **Черновики**: поля в рамке заполняет владелец |
| `assets/css/` | стили, семь файлов, порядок подключения важен — см. ниже |
| `assets/js/` | точка входа `main.js` и двенадцать модулей в `modules/` |
| `assets/fonts/` | Unbounded, Golos Text, JetBrains Mono — шесть woff2, 178 КБ |
| `assets/img/` | логотип, знак, обложка соцсетей, рендеры сцен, фото основателя |
| `assets/video/` | видео первого экрана (947 КБ) и полное промо (4,7 МБ) |
| `api/lead.php` | приём заявки: письмо на почту и запись в журнал |
| `api/logs/.htaccess` | закрывает журнал заявок от доступа снаружи |
| `robots.txt` | сейчас закрывает превью от индексации |
| `README.md` | как устроена вёрстка и почему именно так |
| `TEXT-V2.md` | редакция текстов, принятые решения, открытые вопросы к клиенту |

Чего в архиве нет: исходников рендеров (`visual/`, 74 МБ), оригиналов видео
и скриншотов, пакетов ТЗ и дизайн-бандла — это рабочие материалы студии.
Всё, что нужно странице, лежит внутри в пережатом виде.

## Как запустить локально

```
python -m http.server 8000
```

и открыть `http://127.0.0.1:8000/`.

**Просто открыть `index.html` двойным кликом не получится**: скрипты подключены
как ES-модули, а по `file://` браузер блокирует их политикой CORS. Страница
отрисуется, но без переключателя вкладок, плеера, гамбургера и подстановки цен.

Форма при этом не отправляется — для неё нужен PHP.

## Два места, где легко сломать

### 1. Порядок подключения CSS

```
tokens → base → components → sections → responsive → motion → overrides
```

`overrides.css` **обязан грузиться последним**. В нём лежат правила, которые
намеренно спорят с адаптивом и выигрывают только за счёт порядка: например,
полоса цифр уходит в две колонки с 1280px, а не с 860px, как в базовой сетке.
Если при интеграции стили будут склеиваться или минифицироваться — порядок
нужно сохранить. Слить `overrides.css` с `sections.css` нельзя: `responsive.css`
идёт после и вернёт свои значения.

### 2. Скрипты — модули, а не бандл

`main.js` подключён как `<script type="module">`. Импорты обычные, относительные —
если проект собирается любым бандлером, соберётся как есть. Каждый модуль
обёрнут в `safe()`: упавший модуль пишет ошибку в консоль с именем и не уносит
за собой остальные. Форма обязана работать, даже если сломался плеер.

## Где что менять

| Что | Где |
|---|---|
| Цены тарифов | `assets/js/config.js` → `pricing`. Скидка годового и строка «вместо N ₽» считаются из этих чисел |
| Телефон, почта, Telegram | `assets/js/config.js` → `contacts`. Отсюда собираются все ссылки страницы |
| Тексты режимов формы | `assets/js/config.js` → `lead.modes` |
| Включить или убрать секцию | `assets/js/config.js` → `sections` |
| Счётчик Метрики | `assets/js/config.js` → `analytics.yandexCounterId` |
| Почта, куда падают заявки | `api/lead.php` → `MAIL_TO`, `MAIL_FROM` |
| Домен | `index.html`: `canonical`, `og:url`, `og:image`; плюс `robots.txt` |
| Тексты документов | `docs/*.html` — там же поля в рамке, которые нужно заполнить |

Цены названы ещё в двух местах статикой: в ответе «Есть бесплатная версия?»
и в микроразметке внизу `index.html`. При смене цены поправить и там —
предупреждение об этом стоит прямо в разметке.

## Что учесть при переносе к сервису

**Форма.** Отправляет `FormData` методом POST на `config.form.endpoint`
(по умолчанию `api/lead.php`). Ответ ожидается в виде `{"ok": true}` либо
`{"ok": false, "error": "текст"}`. Если приём заявок переедет на бэкенд сервиса —
достаточно поменять адрес в конфиге, формат ответа оставить прежним.

**Журнал заявок.** `api/logs/leads.log` содержит персональные данные. На Apache
каталог закрывает лежащий рядом `.htaccess`; **на nginx он не работает** — нужно
правило в конфиге сайта, оно записано внутри самого файла. Проверьте это до
первой настоящей заявки.

**Режим превью.** Пока страница живёт на `github.io`, форма не отправляется
и показывает честную плашку, а сама страница закрыта от индексации. Включается
это по домену (`config.preview.hosts`), на боевом домене отключится само.

**Сторонних запросов страница не делает.** Шрифты лежат внутри, аналитики пока
нет. Единственное, что уйдёт наружу после запуска, — счётчик Метрики, когда его
подключат.

**Почта.** `MAIL_FROM` должен быть на домене сайта, а домену нужны SPF и DKIM,
иначе письма с заявками уедут в спам.

## Что обязательно сделать до боевого запуска

1. **Данные оператора** — наименование, ИНН, ОГРН, адрес — в `docs/privacy.html`
   и `docs/requisites.html`. Без них публиковать документы нельзя, а без
   опубликованной политики нельзя собирать данные через формы (ч. 2 ст. 18.1
   ФЗ-152).
2. **Уведомление в Роскомнадзор** об обработке персональных данных — подаётся
   до начала сбора.
3. **Публичная оферта** на подписку: тарифы на странице есть, условий продажи нет.
4. **Домен** в `canonical`, `og:url`, `og:image` и новый `robots.txt` — внутри
   файла записано, чем заменить содержимое. Плюс `sitemap.xml`, которого пока нет.
5. **Закрыть `api/logs/`** правилом веб-сервера, если это не Apache.
6. **Счётчик Метрики**: цели `demo_click`, `trial_request`, `supplier_request`,
   `lead_form_submit` уже расставлены и вызываются, уходить им пока некуда.

## Что осталось незакрытым

- **Оплаты на странице нет.** Кнопки тарифов ведут на форму заявки — она
  подстраивается и просит телефон, но счёт выставляется вручную.
- **Отзывы салонов** закомментированы в `index.html` до реальных цитат: разметка
  на месте, вернуть — снять маркеры комментария.
- **`<title>`, description и og-теги** — единственный текст страницы, который
  клиент ещё не пересматривал. Формулировки там от прежней редакции и обещают
  заметно больше, чем нынешний текст.
- **На реальных устройствах страницу не гоняли**: проверялась в headless Chrome
  на ширинах от 360 до 1440. Отдельно стоит посмотреть iOS Safari — там свои
  особенности с `svh` в высоте первого экрана, автоплеем видео и sticky-шапкой.
- **`deploy.sh` не написан** — боевой хостинг пока не известен. Сейчас публикация
  идёт пушем в `main`, дальше GitHub Pages собирает превью сам.
